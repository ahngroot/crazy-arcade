# 8단계 최종 점검과 인수인계

이번 변경: 바닥 아이템은 12초 유지(기존 6초의 두 배), 마지막 1.5초 페이드는 유지한다. 물풍선 표시의 수직 이동을 4~6px로 강화하고 바닥 그림자는 높이에 따라 변한다. 지정 유튜브/공식 사이트는 프록시 403으로 차단되어 캐릭터 옆모습 재작화·영상 동일성 대조는 미완료다. 영상 확인 없이 외형 전체를 재현했다고 표시하지 않는다. [접근 상태와 남은 작업](reference-video.md)을 따른다. 아래 6초 안내는 이전 버전의 기록이다.

최신 검증: 타입 검사·제품 빌드·규칙/소켓 129개·전체 Chromium E2E 34개 통과. 겹침 입력 우선순위·키 반복 무시·짧은 턴 보존·원래 방향 복귀·막힌 턴 처리·서버 입력 검증, 착지 후 6초 만료와 만료 후 픽업 금지·렌더러의 50%/0% 페이드, 갇힘 숫자 제거와 사망/재생성을 확인했다. ZIP은 최신 소스로 생성하고 CRC·SHA-256을 확인한다.

최신 변경: 방향키를 겹쳐 누르면 새 방향으로 꺾고 보조 키를 떼면 기존 방향으로 돌아갑니다. 바닥 아이템은 6초 유지하며 마지막 1.5초에 옅어져 사라집니다(사망 드롭은 착지부터 계산). 갇힘 5초 판정은 유지하며 남은 초 표시는 제거했습니다.

최신 화면/조작 갱신: 사망 위치에서 아이템이 빈 타일까지 포물선으로 날아가 착지한다. 캐릭터 그림의 투명 여백을 줄이고, 바닥 아이템을 가로/세로 1.5배로 키웠다. 타일 중심을 따라 연속 이동하며 중심에서 정지/회전한다. 화면에 맞춰 경기장을 확대하고 작은 화면의 상태 패널은 아래로 배치한다. 자세한 범위는 [play-feel.md](play-feel.md)를 따른다.

검증: 타입 검사·제품 빌드·규칙/소켓 124개·전체 Chromium E2E 33개 통과. 사망 비행/착지 실제 캡처와 타일 중심 정지·회전·벽 충돌, 빈 타일의 착지와 비행 중 픽업 금지, 확대 화면의 버튼 배치·작은 화면·온라인 재접속/재대결을 확인했다. 최신 Windows ZIP을 재생성하며 CRC·SHA-256을 확인한다. Windows 실제 실행은 해당 커밋의 CI 결과와 구분한다.

최신 랜덤 맵: maps.ts의 7종 카탈로그를 두 제품 모드에 연결했다. 연습은 브라우저 시드, 온라인은 서버 시드로 직전 맵을 제외하고 선택한다. 빈 타일의 무작위 시작·같은 영역·안전 거리를 확인한다. 사망과 재접속은 맵을 보존한다. 공유 맵의 몬스터·드롭·재생성에는 인위적 좌우 구분이 없다. legacy 생성 함수는 fixture로 유지하며 확장 방법은 [maps.md](maps.md)를 따른다.

검증: 타입 검사·제품 빌드·Vitest 121개 통과. Chromium 전체 실행에서 31개 통과 후 온라인 1개 검사의 두 화면 카운트다운 관찰을 동시 실행으로 고쳐 통과했다(32개 항목). 새 7종을 실제 렌더러로 캡처하고 빈 타일·무작위 위치·공유 상태·초기화·선택 캐릭터 유지·사망 후 기본 스펙을 확인했다. Node/PATH 없는 Linux 포터블 실행, Windows ZIP CRC·루트 SHA-256 확인 완료. Windows 실행/실제 PC 두 대 실측과는 구분한다.

최신 이름 변경: shared/characters.ts의 표시 이름 13개를 사용자 지정으로 바꿨다. 추가 요청에 따라 노랑 후드는 슈퍼 케피로 변경했다. ID와 그림·스펙은 그대로이며 긴 이름은 선택 카드에서 줄바꿈한다.

타입 검사·제품 빌드·Vitest 115개·캐릭터/메뉴 Chromium 검사 4개 통과. 이번 텍스트 변경은 전체 E2E를 반복하지 않고 관련 선택·온라인·메뉴·작은 화면 검사로 확인했다.

최신 사망 드롭: game.ts의 defeatPlayer로 익사/추격 사망을 통합했다. 남은 액티브와 영구 개수/속도 강화량만 공유 RNG로 자기 진영의 주변 바닥에 흩뿌리고, 물줄기/울트라를 포함해 능력치와 버프·보관함을 초기화한다. 선택 외형·점수는 유지한다. 공간 부족 시 겹쳐 배치해 수량을 보존하고, 실제 부활 후 0.5초까지 픽업을 차단해 즉시 재획득을 막는다. 이미 사용/교체한 아이템은 복제하지 않는다.

검증: 타입 검사·제품 빌드·Vitest 115개·Chromium E2E 23개 통과. death-drops.test.ts의 6개 테스트로 드롭 수량/종류·기본 스펙·물줄기 제외·시드 결정성·중복 방지·공간 부족·지연된 부활·온라인 상대 불변을 확인했다. 새 Windows ZIP 생성·CRC·체크섬 확인 완료.

최신 스피드업/보관: 첨부 기반 speed.png를 바닥/안내에 공유한다. 사용자의 확인에 따라 2칸을 채운 후 새 아이템은 가장 오래된 것을 버리고 최근 2개로 갱신한다. HUD는 1번/2번을 명시하고 Ctrl은 1번부터 사용한다. 미사용 바늘도 새 픽업으로 교체할 수 있다. 패시브는 저장/교체하지 않는다. 아래 바닥에 남기는 과거 규칙보다 우선한다.

검증: 타입 검사·제품 빌드·Vitest 109개·Chromium E2E 23개 통과. [A,B]→[B,C]의 실제 픽업·Ctrl 소모, 중복/연속 획득, 패시브 불변을 검사했다. 새 ZIP 생성·CRC·체크섬 확인 완료.

최신 설치 풍선 정정: 개수 +1 아이템과 Space 설치 외형을 분리했다. 설치 풍선은 placed-balloon.png의 보라색 구체로 통일하고 기존 ultra 외형 플래그는 제거했다. renderer의 반짝임·흔들림·회전·맥동만 바꾸고 게임 규칙은 유지한다. passive-items.png는 기존 3종 아이템용으로 유지한다.

검증: 타입 검사·제품 빌드·Vitest 108개・전체 Chromium E2E 22개와 전용 시각 검사 1개 통과. 풍선 영역 캡처 `placed-balloon-first.png`, `placed-balloon-shimmer.png`의 변화와 판정 상태 불변을 확인했다. 새 Windows ZIP 생성·CRC·체크섬 확인 완료.

최신 확률/이미지: 울트라만 상자당 7.5%에서 3.75%로 절반 낮추고 전체 드롭률은 유지했다. drops.ts 가중 추첨을 60개 동일 구간으로 전수 검증한다. passive-items.png의 3칸 이미지를 아이템·HUD·설치 풍선에 공유한다. 울트라 패시브 획득 시의 ultra 플래그는 보라색 설치 풍선 외형에만 사용한다.

검증: 타입 검사·제품 빌드·Vitest 108개·Chromium E2E 22개 통과。새 아이템 갤러리 표시, 확률 구간 전수 검사, 일반/울트라 외형 플래그를 확인했다. Windows ZIP 재생성·CRC·체크섬 검증 완료.

최신 캐릭터 선택: 첨부 기반 외형 13종을 메뉴 라디오 버튼으로 제공하고 로컬 저장한다. 온라인 입장 요청의 characterId를 서버가 검증·좌석에 보존해 게임 상태로 공유한다. 연습 재시작 및 온라인 재대결/재접속에 유지한다. 규칙은 외형 값을 읽지 않으므로 모든 스펙이 같다. 정면 원화를 활용한 반전·보행 흔들림이며 별도 방향 원화는 없다.

검증: 타입 검사·제품 빌드·Vitest 106개·Chromium E2E 22개 통과. 13종 같은 능력치, 잘못된 ID 거부, 재접속 시 외형 유지, 연습 선택/재시작/저장 복원, 온라인의 상대별 외형 분리를 확인했다. 새 Windows ZIP 생성·CRC·SHA-256 확인 완료.

바늘·쉴드 복구: 몬스터 보상에만 있던 두 아이템을 공통 상자 드롭에도 넣어 1인 연습에서 획득할 수 있게 했다. 획득 시 보관·합계 2칸·Ctrl FIFO를 확인하는 실제 엔진 픽업 테스트를 추가했다. 첨부 기반 픽셀 시트를 PNG로 번들에 포함하고 바닥과 HUD에 같은 그림을 사용한다.

타입 검사·제품 빌드·Vitest 104개·Chromium E2E 20개 통과. 새 Windows ZIP 재생성·CRC·체크섬 검증 완료. 바늘·쉴드 그림은 첨부 기반 재현이며 원본 픽셀과 완전히 동일한 추출물은 아니다.

최신 테스트 규칙: 액체·롤러스케이트·울트라는 패시브(즉시 적용·만료/슬롯/Ctrl 없음), 울트라는 최대 물줄기다. 장갑·신발·고스트는 공통 드롭과 제품 안내에서 제외하되 구현은 보존했다. 연습과 온라인 모두 적용한다. 아래 6초 울트라/장비 기록은 이전 버전이다.

이번 검증: 타입 검사·제품 빌드·Vitest 103개·Chromium E2E 20개 통과. 가득 찬 보관 칸에서 울트라 즉시 획득·시간 경과 후 유지, 100개 시드의 보류 장비 미출현을 확인했다. 배포 ZIP 갱신·CRC·체크섬 검증 완료.

## 2026-11-09 최신 인게임 변경

연습·온라인·재대결에서 시작 아이템을 제거했다. 갇히면 5초 동안 기본속도×0.4로 이동하고 설치·획득은 금지한다. 호흡·질식·파열·쓰러짐·페이드 후 기존 재생성을 유지한다. 이미지 참고 아이템 6종을 그래픽·능력으로 반영했다. 새 사용 아이템도 합계 2칸 FIFO Ctrl를 따른다. 수치와 검증 한계는 [규칙](rules.md)의 최신 항목을 따른다. 아래 시작 지급·검사 기록은 과거 버전의 기록이다.

검증: 타입 검사·제품 빌드·Vitest 101개, 전체 Chromium E2E 19개 및 추가 실제 갇힘 플레이 1개 통과. Windows ZIP 재생성 및 압축/체크섬 검증 완료. 새 아이템 FIFO·만료·최대 물줄기·밀기·던지기·클라이언트 예측에서 물풍선 불변을 공통 엔진 테스트로 확인했다. Windows의 이번 실행 검사는 CI 결과를 별도로 확인한다.

## 시작 연출과 일반 대결형 연습 맵

1인 연습·온라인 대전·재시작·재대결에서 경기장 중앙에 **3 → 2 → 1 → Game Start!**를 표시한다. 숫자는 1초씩 표시하며 3초 동안 이동·물풍선·아이템과 경기 판정은 멈춘다. Game Start!부터 플레이하며 해당 문구는 1초 뒤 사라진다. 온라인 카운트다운은 서버 시각을 따르고, 진행 중 재접속에는 3초를 다시 붙이지 않는다.

1인 연습은 꼬물이 맵 대신 중앙 분리벽 없는 15×13 일반 대결형 맵을 사용한다. 안전한 시작 칸, 격자형 고정 기둥, 부술 수 있는 색상 블록과 통로가 있으며 바닥은 진영 구분 없는 체크 타일이다. 블록을 부수면 맵 전체로 이동할 수 있다. 화면과 맵은 직접 제작한 리소스다.

타입 검사·제품 빌드·Vitest **98개**·Chromium E2E **19개**가 통과했다. 카운트다운 중 입력·판정 정지, 1초 단위 문구 전환, 일반 맵의 통로·안전한 시작 위치·상자 보상, 온라인 초기 시작·재대결·취소를 확인했다. Node/PATH 없는 Linux 포터블 파일에서도 새 맵·3→2→1→Game Start!·연습 초기화·온라인 대전을 검증했다.

Windows 자동 검사 [41986915469](https://github.com/ahngroot/crazy-arcade/actions/runs/41986915469)도 성공했다(소스 `b140479`, 1분 35초). Windows에서 98개 테스트·EXE 생성·실제 포터블 실행과 브라우저의 새 맵·3→2→1→Game Start!·연습 초기화·온라인 대전을 확인했다. 저장소에 게시된 ZIP을 다시 다운로드해 SHA-256과 ZIP 무결성, 갱신된 시작 안내도 검증했다.

## 현재 기능: 1인 연습과 온라인 대전

사용자의 정정에 따라 **1인 연습 모드**를 복구했다. 한 PC에서 두 캐릭터를 조작하는 기능만 제거한다. 연습에서는 실제 캐릭터 한 명만 생성하며, 상대·방 참가 없이 시간제한 없이 플레이한다. 방향키·Space·양쪽 Ctrl을 사용하고 보호막→파워 2개로 시작한다. 처음부터 다시는 맵·능력치·아이템을 초기화한다. 온라인 연결 없이도 연습 판정은 클라이언트에서 진행된다.

타입 검사·제품 빌드·Vitest **95개**·Chromium E2E **17개**가 통과했다. 온라인 연결을 차단한 상태의 1인 연습, 아이템 FIFO, 물풍선·재생성·상자 보상·초기화, 연습→온라인→연습 전환을 확인했다. Node/PATH 없는 Linux 포터블 실행에서도 1인 연습과 온라인 대전을 모두 검사했다.

복구 버전의 [Windows 자동 검사 41983751701](https://github.com/ahngroot/crazy-arcade/actions/runs/41983751701)도 성공했다(소스 `62f336d`, 2분 6초). Windows에서 95개 테스트와 EXE 생성, Node/PATH 없는 폴더의 실제 EXE 실행, 1인 연습·초기화·온라인 대전 브라우저 검사를 통과했다. 저장소에 게시된 ZIP을 다시 내려받아 SHA-256·ZIP 무결성·1인 연습 안내도 확인했다.

메뉴와 Windows EXE 모두 **1인 연습 모드 / 온라인 대전**을 제공한다. 아래 온라인 전용 전환 기록은 복구 이전의 이력이며 현재 기능 안내로 적용하지 않는다.

## 2026-11-05 온라인 전용 전환

- 제품 메뉴는 온라인 대전만 제공한다. 로컬 2인·무제한 연습과 클라이언트의 로컬 경기 실행 경로를 제거했다.
- 각 PC는 한 캐릭터만 조작한다. 빨강·초록 모두 방향키 이동, Space 물풍선, 양쪽 Ctrl 아이템이다. 보관 한도 2개와 획득 순서 사용은 유지한다.
- EXE 호스트는 같은 LAN의 상대 접속을 받는다. 초대 주소는 선택한 LAN IP와 화면의 포트를 사용하며, 상대는 브라우저로 참가한다.
- 타입 검사·빌드·Vitest 93개·Chromium E2E 14개 통과. 두 팀의 입력 분리, Ctrl 겹침/길게 누름, 초대 코드, 재접속·재대결·서버 재시작·좁은 화면·음향을 확인했다.
- Linux 포터블 파일을 Node/PATH 없는 한글 폴더에서 실행해 실제 소켓 2명과 브라우저 2명의 온라인 대전·방향키·Space·Ctrl을 확인했다. Windows ZIP은 별도로 생성하며 체크섬과 무결성을 검사한다.

이 클라우드의 Chromium은 사설 IP로 이동하면 네트워크 정책의 `Domain forbidden` 응답을 받는다. 여기서는 `PLAYWRIGHT_LOOPBACK_INVITES=1`, `PORTABLE_BROWSER_LOOPBACK=1`로 같은 서버의 루프백 주소에서 두 독립 브라우저를 검증했다. LAN 주소 생성·포트·전체 IPv4 바인딩을 확인했지만 이를 실제 PC 두 대의 LAN 실측으로 표시하지 않는다. Windows CI의 포터블 검사는 기본 설정으로 감지된 LAN 주소를 사용한다.

Windows 자동 빌드도 [실행 41958014533](https://github.com/ahngroot/crazy-arcade/actions/runs/41958014533)에서 성공했다(소스 `f374338`, 2분 13초). Windows에서 93개 테스트, EXE 생성, Node/PATH 없는 폴더에서 실제 실행, 두 브라우저 온라인 대전 검사를 통과하고 배포 파일과 화면 artifact를 생성했다. 실제 사용자 PC 두 대의 인터넷 회선 검증과는 구분한다.

공개 인터넷 서버는 계속 미배포 상태다. 아래 과거 단계/빌드 기록은 당시 기능과 검증 범위다.

후속으로 Node.js 설치 없이 실행하는 Windows 포터블 EXE 테스트 빌드를 추가했다. 사용·제작·실제 검증 범위는 [windows.md](windows.md)를 따른다. 아래 소스 개발 방법의 Node.js 24 요구는 EXE를 실행하는 사용자에게 적용되지 않는다.

## 후속 변경 (2026-11-04)

게임 이름은 **crazy myangcade / 크레이지 먕케이드**로 변경했다. 사용 아이템은 합계 2개의 FIFO 보관 칸에 저장하며 Ctrl 한 번당 먼저 획득한 하나를 사용한다. 현재 1인 연습과 온라인 대전에서 방향키·Space·양쪽 Ctrl로 내 캐릭터만 조작한다. 보호막→파워로 시작하고 가득 찼을 때 새 사용 아이템은 바닥에 남는다. 바늘이 맨 앞이면 갇힌 상태에서만 사용할 수 있다. 능력치 강화는 즉시 적용한다. 빠른 누름·뗌·재누름을 로컬 및 네트워크 송신 주기 사이에서도 순서대로 보존한다.

현재 한 PC의 로컬 2인 플레이만 제거했다. 혼자 하려면 1인 연습 모드를 선택한다. EXE 한 개를 호스트에서 실행하고 같은 LAN의 상대가 초대 주소로 접속한다. 자세한 실행법은 [Windows 안내](windows.md)를 따른다.

아래 8단계 실행 기록은 2026-11-03 당시 결과다. 최신 조작법은 [README](../README.md#조작)를 따른다.

변경 후 타입 검사·제품 빌드·Vitest 83개·Chromium Playwright 16개가 통과했다. 합계 2개 제한·FIFO·미사용 바늘 보존·초과 아이템 바닥 유지·누른 채 반복 방지·빠른 Ctrl 연속 입력·두 플레이어 분리·온라인 중복 입력 방지를 검증했다. 새 메뉴 화면은 `test-results/menu-desktop.png`, Ctrl 사용 후 두 칸 UI는 `test-results/items-ctrl.png`에 생성된다.

## 완료 범위

2026-11-03 기준, 로컬 2인·무제한 연습·같은 서버의 온라인 2인 게임을 인수인계한다. 1~6단계 구현과 자동 QA를 바탕으로 실행 안내, 원작 비교, 설정 위치, 알려진 문제와 후속 확인 절차를 정리했다. 사용자 요청으로 7단계 공개 배포를 보류했으므로 Docker/Render 설정과 공개 게임 주소는 없다. 원작 실측·Windows·공개 인터넷 검증은 남아 있다.

## 실행과 작업 이어가기

새 PC는 Git과 Node.js 24.x를 설치하고 저장소를 내려받는다.

```sh
git clone https://github.com/ahngroot/crazy-arcade.git
cd crazy-arcade
node --version
npm ci
npm run dev
```

터미널을 켜 둔 채 **http://localhost:5173**에 접속한다. 온라인 대전에서 방을 만들거나 참가하고, 소리가 필요하면 **소리 켜기**를 누른다. 종료는 Ctrl+C다. 조작표는 [README](../README.md#조작)를 참고한다.

기존 체크아웃은 `git status`로 자신의 변경을 확인하고 보존한 뒤 `git pull --ff-only origin main`, `npm ci`로 갱신한다. Codex에 저장소를 연결하면 다음 PC에서도 작업을 이어갈 수 있다. GitHub에는 소스·테스트·잠금 파일·문서가 저장되며 실행 프로세스·방·브라우저 저장소는 옮겨지지 않는다.

### 빌드한 게임 실행

개발 서버를 먼저 종료한 뒤 저장소 루트에서:

```sh
npm run build
npm start
```

**http://localhost:3001**에 접속한다. 빌드한 화면과 Socket.IO를 같은 서버가 제공한다. 기본 3001에 바인딩하며 `0.0.0.0`으로 같은 네트워크의 접속을 받는다. 별도 DB·API 키·회원 계정이 필요하지 않다. `.env` 파일을 자동으로 읽지는 않는다.

포트를 바꾸려면 실행 프로세스의 `PORT`를 설정한다. 예를 들어 PowerShell:

```powershell
$env:PORT = "3002"
npm start
```

Linux/macOS는 `PORT=3002 npm start`를 사용한다. 이때 주소도 `http://localhost:3002`다. 개발 실행은 클라이언트 프록시가 3001을 사용하므로 기본 포트를 유지한다.

### 같은 공유기에서 두 PC로 테스트

1. 호스트 PC에서 개발 실행(5173) 또는 빌드 실행(기본 3001) 중 하나를 시작한다.
2. 호스트의 사설 IPv4를 확인한다. Windows는 `ipconfig`, Linux는 `ip -4 addr`로 볼 수 있다.
3. 다른 PC에서 `http://호스트-IP:5173` 또는 빌드 실행의 `http://호스트-IP:3001`을 연다. 호스트의 해당 포트가 로컬 방화벽에서 허용되어야 한다. 공유기의 게스트 네트워크/단말 격리가 있으면 서로 접근할 수 없다.
4. 각자 온라인 대전으로 들어가 닉네임 입력→방 생성/코드 참가→양쪽 READY로 시작한다.

상대 PC의 `localhost`는 상대 자신을 뜻한다. Codex 클라우드는 사용자 PC와 같은 LAN이 아니며, 클라우드 localhost를 사용자 PC에서 바로 열 수 없다. 서로 다른 집에서 접속하는 공개 서버 설정은 보류한 7단계 범위다. GitHub 저장소 페이지 자체는 게임 서버가 아니다.

| 지원 범위 | 모바일 터치·계정·영구 전적·맵 편집기 없음                     | 기능별 요청 시 범위 확정                                                                              |

20개 방 측정은 엔진/스냅샷 생성만 포함하므로 운영 동접 보장이 아니다. 지연 시뮬레이션은 실제 인터넷 검증이 아니다. 상세 성능 근거는 [qa.md](qa.md)를 참고한다.

## 코드와 리소스 인수인계

| 경로                                                   | 책임                                      |
| ------------------------------------------------------ | ----------------------------------------- |
| `packages/shared/src/index.ts`                         | 공통 타입·`GAME_CONFIG`                   |
| `packages/shared/src/game.ts`, `competition.ts`        | 이동·충돌·물풍선·아이템·몬스터·점수·승패  |
| `apps/server/src/rooms.ts`                             | 방·세션·서버 판정·입력 검증               |
| `apps/server/src/app.ts`, `index.ts`                   | HTTP/Socket.IO·정적 클라이언트·시작/종료  |
| `apps/client/src/main.ts`, `game.ts`                   | 메뉴·HUD·키보드·게임 수명주기             |
| `apps/client/src/online.ts`, `netcode.ts`              | 방 UI·재접속·예측·보정·보간               |
| `art.ts`, `renderer.ts`, `presentation.ts`, `audio.ts` | 직접 작성한 그림·표시·연출 관찰·합성 음악 |
| `tests/`, `scripts/benchmark.ts`                       | 실제 브라우저 검사·성능 재현              |

캐릭터·타일·아이템·로고 그림과 음악/효과음은 코드로 직접 작성했다. 클라이언트 소스에서 외부 이미지·음원·폰트 로딩을 찾지 못했으며, SVG의 `www.w3.org`는 네임스페이스 문자열이다. 원작 리소스 파일은 포함하지 않는다. npm의 Phaser/Express/Socket.IO 등 외부 라이브러리는 각 패키지 라이선스를 유지한다.

생성 결과·`node_modules`·`dist`·로컬 설정/비밀값은 커밋하지 않는다. 이후 변경도 검증 후 커밋하고 `git push origin HEAD:main`으로 반영한다. 기존 사용자 변경은 보존하며 강제 푸시하지 않는다.
