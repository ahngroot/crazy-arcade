# 8단계 최종 점검과 인수인계

## 현재 기능: 1인 연습과 온라인 대전

사용자의 정정에 따라 **1인 연습 모드**를 복구했다. 한 PC에서 두 캐릭터를 조작하는 기능만 제거한다. 연습에서는 실제 캐릭터 한 명만 생성하며, 상대·방 참가 없이 시간제한 없이 플레이한다. 방향키·Space·양쪽 Ctrl을 사용하고 보호막→파워 2개로 시작한다. 처음부터 다시는 맵·능력치·아이템을 초기화한다. 온라인 연결 없이도 연습 판정은 클라이언트에서 진행된다.

타입 검사·제품 빌드·Vitest **95개**·Chromium E2E **17개**가 통과했다. 온라인 연결을 차단한 상태의 1인 연습, 아이템 FIFO, 물풍선·재생성·상자 보상·초기화, 연습→온라인→연습 전환을 확인했다. Node/PATH 없는 Linux 포터블 실행에서도 1인 연습과 온라인 대전을 모두 검사했다.

복구 버전의 [Windows 자동 검사 41983751701](https://github.com/ahngroot/crazy-arcade/actions/runs/41983751701)도 성공했다(소스 `62f336d`, 2분 6초). Windows에서 95개 테스트와 EXE 생성, Node/PATH 없는 폴더의 실제 EXE 실행, 1인 연습·초기화·온라인 대전 브라우저 검사를 통과했다. 저장소에 게시된 ZIP을 다시 내려받아 SHA-256·ZIP 무결성·1인 연습 안내도 확인했다.

메뉴와 Windows EXE 모두 **1인 연습 모드 / 온라인 대전**을 제공한다. 아래 온라인 전용 전환 기록은 복구 이전의 이력이며 현재 기능 안내로 적용하지 않는다.

## 2026-11-05 온라인 전용 전환

- 제품 메뉴는 온라인 대전만 제공한다. 로컬 2인·무제한 연습과 클라이언트의 로컬 경기 실행 경로를 제거했다.
- 각 PC는 한 캐릭터만 조작한다. 빨강·초록 모두 방향키 이동, Space 물풍선, 양쪽 Ctrl 아이템이다. 보관 한도 2개와 획득 순서 사용은 유지한다.
- EXE 호스트는 같은 LAN의 상대 접속을 받는다. 초대 주소는 선택한 LAN IP와 화면의 포트를 사용하며, 상대는 브라우저로 참가한다.
- 타입 검사·빌드·Vitest 93개·Chromium E2E 14개 통과. 두 팀의 입력 분리, Ctrl 겹침/길게 누름, 초대 코드, 재접속·재대결·서버 재시작·좁은 화면·음향을 확인했다.
- Linux 포터블 파일을 Node/PATH 없는 한글 폴더에서 실행해 실제 소켓 2명과 브라우저 2명의 온라인 대전·방향키·Space·Ctrl을 확인했다. Windows ZIP은 별도로 생성하며 체크섬과 무결성을 검사한다.

이 클라우드의 Chromium은 사설 IP로 이동하면 네트워크 정책의 `Domain forbidden` 응답을 받는다. 여기서는 `PLAYWRIGHT_LOOPBACK_INVITES=1`, `PORTABLE_BROWSER_LOOPBACK=1`로 같은 서버의 루프백 주소에서 두 독립 브라우저를 검증했다. LAN 주소 생성·포트·전체 IPv4 바인딩을 확인했지만 이를 실제 PC 두 대의 LAN 실측으로 표시하지 않는다. Windows CI의 포터블 검사는 기본 설정으로 감지된 LAN 주소를 사용한다.

Windows 자동 빌드도 [실행 41958014533](https://github.com/ahngroot/crazy-arcade/actions/runs/41958014533)에서 성공했다(소스 `f374338`, 2분 13초). Windows에서 93개 테스트, EXE 생성, Node/PATH 없는 폴더에서 실제 실행, 두 브라우저 온라인 대전 검사를 통과하고 배포 파일과 화면 artifact를 생성했다. 실제 사용자 PC 두 대의 인터넷 회선 검증과는 구분한다.

공개 인터넷 서버는 계속 미배포 상태다. 아래 과거 단계/빌드 기록은 당시 기능과 검증 범위다.

후속으로 Node.js 설치 없이 실행하는 Windows 포터블 EXE 테스트 빌드를 추가했다. 사용·제작·실제 검증 범위는 [windows.md](windows.md)를 따른다. 아래 소스 개발 방법의 Node.js 24 요구는 EXE를 실행하는 사용자에게 적용되지 않는다.

## 후속 변경 (2026-11-04)

게임 이름은 **crazy myangcade / 크레이지 먕케이드**로 변경했다. 사용 아이템은 합계 2개의 FIFO 보관 칸에 저장하며 Ctrl 한 번당 먼저 획득한 하나를 사용한다. 현재 1인 연습과 온라인 대전에서 방향키·Space·양쪽 Ctrl로 내 캐릭터만 조작한다. 보호막→파워로 시작하고 가득 찼을 때 새 사용 아이템은 바닥에 남는다. 바늘이 맨 앞이면 갇힌 상태에서만 사용할 수 있다. 능력치 강화는 즉시 적용한다. 빠른 누름·뗌·재누름을 로컬 및 네트워크 송신 주기 사이에서도 순서대로 보존한다.

현재 한 PC의 로컬 2인 플레이만 제거했다. 혼자 하려면 1인 연습 모드를 선택한다. EXE 한 개를 호스트에서 실행하고 같은 LAN의 상대가 초대 주소로 접속한다. 자세한 실행법은 [Windows 안내](windows.md)를 따른다.

아래 8단계 실행 기록은 2026-11-03 당시 결과다. 최신 조작법은 [README](../README.md#조작)를 따른다.

변경 후 타입 검사·제품 빌드·Vitest 83개·Chromium Playwright 16개가 통과했다. 합계 2개 제한·FIFO·미사용 바늘 보존·초과 아이템 바닥 유지·누른 채 반복 방지·빠른 Ctrl 연속 입력·두 플레이어 분리·온라인 중복 입력 방지를 검증했다. 새 메뉴 화면은 `test-results/menu-desktop.png`, Ctrl 사용 후 두 칸 UI는 `test-results/items-ctrl.png`에 생성된다.

## 완료 범위

2026-11-03 기준, 로컬 2인·무제한 연습·같은 서버의 온라인 2인 게임을 인수인계한다. 1~6단계 구현과 자동 QA를 바탕으로 실행 안내, 원작 비교, 설정 위치, 알려진 문제와 후속 확인 절차를 정리했다. 사용자 요청으로 7단계 공개 배포를 보류했으므로 Docker/Render 설정과 공개 게임 주소는 없다. 원작 실측·Windows·공개 인터넷 검증은 남아 있다.

## 실행과 작업 이어가기

새 PC는 Git과 Node.js 24.x를 설치하고 저장소를 내려받는다.

```sh
git clone https://github.com/ahngroot/crazy-arcade.git
cd crazy-arcade
node --version
npm ci
npm run dev
```

터미널을 켜 둔 채 **http://localhost:5173**에 접속한다. 온라인 대전에서 방을 만들거나 참가하고, 소리가 필요하면 **소리 켜기**를 누른다. 종료는 Ctrl+C다. 조작표는 [README](../README.md#조작)를 참고한다.

기존 체크아웃은 `git status`로 자신의 변경을 확인하고 보존한 뒤 `git pull --ff-only origin main`, `npm ci`로 갱신한다. Codex에 저장소를 연결하면 다음 PC에서도 작업을 이어갈 수 있다. GitHub에는 소스·테스트·잠금 파일·문서가 저장되며 실행 프로세스·방·브라우저 저장소는 옮겨지지 않는다.

### 빌드한 게임 실행

개발 서버를 먼저 종료한 뒤 저장소 루트에서:

```sh
npm run build
npm start
```

**http://localhost:3001**에 접속한다. 빌드한 화면과 Socket.IO를 같은 서버가 제공한다. 기본 3001에 바인딩하며 `0.0.0.0`으로 같은 네트워크의 접속을 받는다. 별도 DB·API 키·회원 계정이 필요하지 않다. `.env` 파일을 자동으로 읽지는 않는다.

포트를 바꾸려면 실행 프로세스의 `PORT`를 설정한다. 예를 들어 PowerShell:

```powershell
$env:PORT = "3002"
npm start
```

Linux/macOS는 `PORT=3002 npm start`를 사용한다. 이때 주소도 `http://localhost:3002`다. 개발 실행은 클라이언트 프록시가 3001을 사용하므로 기본 포트를 유지한다.

### 같은 공유기에서 두 PC로 테스트

1. 호스트 PC에서 개발 실행(5173) 또는 빌드 실행(기본 3001) 중 하나를 시작한다.
2. 호스트의 사설 IPv4를 확인한다. Windows는 `ipconfig`, Linux는 `ip -4 addr`로 볼 수 있다.
3. 다른 PC에서 `http://호스트-IP:5173` 또는 빌드 실행의 `http://호스트-IP:3001`을 연다. 호스트의 해당 포트가 로컬 방화벽에서 허용되어야 한다. 공유기의 게스트 네트워크/단말 격리가 있으면 서로 접근할 수 없다.
4. 각자 온라인 대전으로 들어가 닉네임 입력→방 생성/코드 참가→양쪽 READY로 시작한다.

상대 PC의 `localhost`는 상대 자신을 뜻한다. Codex 클라우드는 사용자 PC와 같은 LAN이 아니며, 클라우드 localhost를 사용자 PC에서 바로 열 수 없다. 서로 다른 집에서 접속하는 공개 서버 설정은 보류한 7단계 범위다. GitHub 저장소 페이지 자체는 게임 서버가 아니다.

## 검증 결과

최종 검증 명령은 아래와 같다. 브라우저 테스트는 빌드를 포함하며 한 worker로 실행한다.

```sh
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
```

이미 Chromium이 설치된 Linux는 `PLAYWRIGHT_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`로 실행한다. 성능 측정은 `npm run benchmark`다. 테스트 결과와 생성 리소스는 `test-results/`에 저장하며 Git에 넣지 않는다.

2026-11-03, Node.js 24.19.0 / npm 11.9.0 / Linux 시스템 Chromium에서 아래 항목이 모두 통과했다.

| 실행                         | 결과                                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------------------- |
| `npm ci`                     | 잠금 파일 기준 203개 패키지 새 설치 성공                                                                |
| `npm run typecheck`          | 통과                                                                                                    |
| `npm test`                   | 9개 파일, 74개 테스트 통과                                                                              |
| `npm run test:e2e`           | 제품 빌드와 Chromium 16개 검사 통과, 약 2.3분                                                           |
| 빌드한 서버 진입점 직접 실행 | `/health`, HTML·JavaScript 제공, 실제 소켓 2개 입장·READY·PLAYING, 같은 tick의 점수·게임 시간 일치 확인 |
| 리소스·문서 점검             | 외부 게임 에셋 로딩 없음, 로컬 문서 파일 링크 확인                                                      |

메뉴 연결 안내를 빌드 실행에도 맞는 ‘게임 서버 연결됨’으로 정리했다. 메뉴·좁은 화면·그래픽/사운드·로컬/온라인 대전·재접속·재대결·서버 재시작 검사는 모두 이번 최종 실행에 포함됐다. 아래 수동 항목을 수행한 것으로 간주하지 않는다.

20개 방 측정은 엔진/스냅샷 생성만 포함하므로 운영 동접 보장이 아니다. 지연 시뮬레이션은 실제 인터넷 검증이 아니다. 상세 성능 근거는 [qa.md](qa.md)를 참고한다.

## 코드와 리소스 인수인계

| 경로                                                   | 책임                                      |
| ------------------------------------------------------ | ----------------------------------------- |
| `packages/shared/src/index.ts`                         | 공통 타입·`GAME_CONFIG`                   |
| `packages/shared/src/game.ts`, `competition.ts`        | 이동·충돌·물풍선·아이템·몬스터·점수·승패  |
| `apps/server/src/rooms.ts`                             | 방·세션·서버 판정·입력 검증               |
| `apps/server/src/app.ts`, `index.ts`                   | HTTP/Socket.IO·정적 클라이언트·시작/종료  |
| `apps/client/src/main.ts`, `game.ts`                   | 메뉴·HUD·키보드·게임 수명주기             |
| `apps/client/src/online.ts`, `netcode.ts`              | 방 UI·재접속·예측·보정·보간               |
| `art.ts`, `renderer.ts`, `presentation.ts`, `audio.ts` | 직접 작성한 그림·표시·연출 관찰·합성 음악 |
| `tests/`, `scripts/benchmark.ts`                       | 실제 브라우저 검사·성능 재현              |

캐릭터·타일·아이템·로고 그림과 음악/효과음은 코드로 직접 작성했다. 클라이언트 소스에서 외부 이미지·음원·폰트 로딩을 찾지 못했으며, SVG의 `www.w3.org`는 네임스페이스 문자열이다. 원작 리소스 파일은 포함하지 않는다. npm의 Phaser/Express/Socket.IO 등 외부 라이브러리는 각 패키지 라이선스를 유지한다.

생성 결과·`node_modules`·`dist`·로컬 설정/비밀값은 커밋하지 않는다. 이후 변경도 검증 후 커밋하고 `git push origin HEAD:main`으로 반영한다. 기존 사용자 변경은 보존하며 강제 푸시하지 않는다.
