# 화면 크기와 타일 이동, 사망 드롭 연출

최신 검증: 타입 검사·빌드·Vitest138개·전체 Chromium40개 통과. 0~3개 전량/4~5개80% 경계, 울트라를 여러 액체로 복제하지 않음·반복 울트라 비복제·사망 기록 초기화, 자기 캐릭터 화살표 소유권·위치 추적·상단 표시·사망 숨김/부활 재표시, 0.8칸/초 갇힘 이동과 기존 흐름을 확인했다. ZIP CRC·SHA-256을 확인했다. 아래 검증 수치는 이전 단계 기록이다.

최우선 최신 변경: 갇힘 속도0.8칸/초. 내 캐릭터 위의 하늘색 화살표는 첨부 사진을 참고해 self-arrow.png로 재구성했다. 자기 playerId에만 하나 표시하고 이동/갇힘/부활을 따라가며 사망 때 숨긴다. 화면 위쪽에서는 잘리지 않게 표시 위치를 보정한다. 원본 픽셀 추출본은 아니다.

물줄기/울트라도 드롭에 포함한다. 액체는 실제 강화 개수(rangePickups), 울트라는 보유 효과 하나(ultraPickup)를 별도로 기록한다. 울트라로 늘어난 범위를 액체 여러 개로 환산하지 않는다. 대상이 3개 이하면 전부(0→0,1→1,2→2,3→3), 4개 이상이면 80% 버림(4→3,5→4)으로 골라 맵 전체에 비행시킨다. 이미 사용/교체한 액티브, 중복 울트라/상한 초과 액체는 복제하지 않는다. 사망 시 모든 강화/보관함과 기록을 지운다. 아래 과거 제외/속도/소량 버림 기록보다 이 규칙이 우선한다.

최신 검증: 타입 검사·빌드·Vitest 136개 통과. 전체 Chromium 실행에서 38개 통과 후 먼 거리 아이템의 화면 깊이 정렬을 생성 순서로 가정한 비행 검사를 ID 추적으로 수정해 해당 1개를 재검증했다. 총 39개 항목을 확인했다. 새 ZIP CRC·SHA-256을 확인했다. 아래 이전 단계 검증과 구분한다.

최신 사망/부활: 갇힌 속도는 기본 20%(기존 갇힘 속도의 절반, 0.6칸/초)다. 남은 액티브와 개수/속도 강화분을 섞어 floor(N×0.8)개만 드롭한다. 예: 7개→5개, 4개→3개, 1개→0개. 물줄기/울트라는 제외하고 전체 능력치는 초기화한다. 사망 위치 근처의 12개 후보 제한과 거리 정렬을 없애 맵 전체 바닥을 섞어 착지시킨다. 비행·착지 후15초 만료는 유지한다.

부활 위치는 안전한 빈 타일 중 시드 기반 무작위로 정한다. 아이템/물풍선/물줄기/다른 살아 있는 플레이어/위험 거리의 몬스터가 있는 칸은 제외하며, 후보가 없으면 안전한 빈 칸이 생길 때까지 기다린다. 초기 시작 위치와 가까운 순으로 고르던 방식은 제거했다. 같은 입력/시드에서 서버·연습이 재현 가능한 규칙이다.

## 모서리 회전과 짧은 입력 보정

검증: 타입 검사·제품 빌드·규칙/소켓 134개·전체 Chromium 38개 통과. 열린/막힌 모서리 정렬 좌표, 대각선 통과 방지, 새 입력 교체·기존 ID 재보관 방지·350ms 만료·사망 시 삭제와 기존 연습/온라인/부활 흐름을 확인했다. Windows ZIP CRC·SHA-256을 확인했다. 이번 커밋의 Windows 네이티브 실행은 별도 확인이 필요하다.

타일 중심 0.16칸(40px 타일에서 6.4px) 이내에서 다른 축의 방향을 요청하면 그 방향의 다음 칸이 비어 있을 때 중심 정렬 구간만 최대 1.6배로 이동한다. 중심에 도착한 뒤 다음 방향으로 꺾기 때문에 대각선 모서리 통과나 위치 순간이동은 없다. 벽·상자·통과 권한이 없는 설치 물풍선에 막힌 방향에는 보정을 적용하지 않는다. 키를 떼면 이동 중인 칸의 중심까지 마치는 규칙과 벽 앞 제자리 걷기는 유지한다.

짧은 방향 입력은 가장 최근 turnId 하나만 최대 350ms 보관한다. 새 입력은 이전 입력을 교체하며, 만료된 입력은 뒤늦게 실행하지 않고 같은 ID로 보관을 다시 시작하지 않는다. 계속 누르고 있는 방향은 현재 x/y 입력으로 처리하므로 보관 시간 만료 후에도 정상적으로 걷고 회전한다. 느린 갇힘 상태에서 오래전에 떼어 놓은 방향은 다음 중심에 도달하기 전에 만료될 수 있다. 사망·부활에도 대기 입력을 지운다.

공유 movePlayer가 상태의 queuedTurnRemainingMs를 이동 dt로 차감한다. 클라이언트 예측은 경기 시각 자체를 진행하지 않으므로 시각 대신 dt를 사용해 서버와 같은 보관 규칙을 적용한다. 조정 값은 GAME_CONFIG의 gridTurnAssistTiles / gridTurnAssistSpeed / turnBufferMs이다. 새 참고나 플레이 의견에 따라 조정할 수 있다.

최신 변경: 아이템 유지 시간을 17초에서 15초로 2초 앞당겼다. 마지막 3초 페이드는 유지한다. 벽이나 물풍선에 막혀도 방향 입력이 있으면 해당 방향을 바라보며 제자리 걷기를 재생한다. 좌표 이동과 충돌 판정은 유지하고 키를 떼면 멈춘다. 온라인 서버와 클라이언트 예측·연습이 같은 movePlayer를 사용한다. 13종 방향 그림은 [character-motion.md](character-motion.md)를 따른다. 아래 검증 수치는 이전 단계 기록이다.

최신 검증: 타입 검사·제품 빌드·규칙/소켓 129개·전체 Chromium E2E 34개 통과. 겹침 입력 우선순위·키 반복 무시·짧은 턴 보존·원래 방향 복귀·막힌 턴 처리·서버 입력 검증, 착지 후 6초 만료와 만료 후 픽업 금지·렌더러의 50%/0% 페이드, 갇힘 숫자 제거와 사망/재생성을 확인했다. ZIP은 최신 소스로 생성하고 CRC·SHA-256을 확인한다.

최신 방향키: 여러 키를 누르면 새로 누른 방향을 우선하고 그 키를 떼면 기존에 누른 키로 돌아간다. 짧은 추가 입력도 turn/turnId를 통해 다음 타일 중심에서 한 번 실행한다. 키 자동 반복은 우선순위를 바꾸지 않는다. 서버는 방향 문자열/입력 ID를 검사하며 같은 턴 ID를 중복 실행하지 않는다.

모든 바닥 아이템은 생성 후 15초(사망 드롭은 각 착지 후 15초) 동안 유지된다. 마지막 3초 동안 아이템과 그림자가 점점 옅어지고, 만료 시 서버/연습 공통 엔진에서 제거하므로 획득할 수 없다. 시간 숫자는 표시하지 않는다. 물풍선 갇힘의 5초 판정·기포·긴박해지는 호흡 연출은 유지하되 HUD의 남은 초와 5개 점 표시는 제거했다.

캐릭터는 테마 맵에서 상하좌우 한 칸씩 연속 이동한다. 키를 짧게 눌러도 현재 이동 중인 칸의 중심까지 도달한 뒤 정지하고, 다른 방향을 누르면 다음 중심에서 방향을 바꾼다. 보간된 연속 이동이며 화면에서 순간이동하지 않는다. 서버와 클라이언트 예측이 같은 moveTarget 판정을 사용한다. 갇힌 상태는 기본 속도의 20%를 유지하며 사망·재생성 때 이동 목표를 지운다. 과거 레거시 fixture의 자유 이동은 제품에서 사용하지 않는다.

캐릭터 그림의 알파 영역을 측정해 투명 여백을 제거하고 비율을 유지해 캔버스를 채운다. 발 위치와 타일 중심은 유지하며 머리 부분은 위로 올라온다. 바닥 아이템은 기존 27×28.5에서 40.5×42.75로 가로/세로 1.5배 확대했다.

사망 드롭의 서버 상태에는 사망 위치, 시작 시각, 각 아이템의 착지 시각이 들어간다. 700ms부터 아이템마다 45ms 차이를 두고 착지하며 렌더러가 출발점→착지 타일의 포물선·회전·그림자를 그린다. 재접속해도 경기 시각에 맞는 위치를 그린다. 비행 중 픽업은 불가하며 기존 재생성/픽업 지연 규칙은 유지한다. 물줄기·울트라는 드롭하지 않는다.

경기 대화상자를 화면 너비의 99%로 확장하고 반복 안내/여백을 줄여 경기장을 확대했다. 맵 타일 수는 15×13으로 유지한다. 큰 화면은 경기장과 상태 패널을 나란히, 작은 화면은 상태 패널을 아래에 표시한다. 낮은 화면에서는 상태 패널을 별도로 스크롤하며 종료 버튼을 고정한다. 모바일 터치 조작 추가는 이번 변경에 포함하지 않는다.

검증: 타입 검사·빌드·Vitest 124개·전체 Chromium 33개 통과. scatter.spec.ts가 실제 렌더러에서 출발/비행/착지 좌표와 크기·포물선 높이를 검사하고 scatter-flight.png/scatter-landed.png를 캡처한다. 데스크톱 1440×1000에서 온라인 경기장 높이는 기존 약 580px에서 약 720px로 커졌으며 하단 버튼과 겹치지 않는다. 작은 화면의 가로 넘침·종료 접근과 연습/온라인 흐름도 확인했다.
