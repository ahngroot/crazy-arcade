# 6단계: 버그·성능 검증

후속 변경(2026-11-04): crazy myangcade / 크레이지 먕케이드 이름과 Ctrl FIFO·합계 2칸 아이템 규칙에 맞춰 회귀 검사를 갱신했다. 타입 검사·빌드·Vitest 83개·브라우저 16개가 통과했다. 아래 성능 수치는 6단계 당시 측정값이며 두 칸 아이템 변경 후 다시 측정한 수치가 아니다.

## 재현 및 수정

| 재현 조건                                               | 이전 동작                                                                | 수정과 회귀 검증                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| 온라인 화면을 10FPS로 갱신하며 1초 이동                 | 30Hz 입력/예측을 프레임당 한 번만 실행해 10회 처리                       | 누적 시간을 30Hz 단위로 처리. 10/30FPS 이동 거리·송신 수를 비교하고 긴 프레임은 250ms로 제한 |
| 물풍선/특수 버튼을 누름→뗌→다시 누름                    | 뗌 패킷이 volatile이라 유실되면 다음 누름이 이어진 입력으로 남을 수 있음 | 누름과 뗌 전환 모두 신뢰 전송. 버튼별 전환과 지속 이동 샘플을 검사                           |
| 종료→한 명 재대결 준비→상대 끊김→30초 만료→새 상대 입장 | 대기 상태에 이전 경기 결과가 남음                                        | 새 상대 입장 시 종료된 경기와 준비 상태 초기화                                               |
| 이동 중 몬스터의 출발/도착 칸에 모두 물풍선 설치        | 출발 칸의 물풍선 쪽으로 되돌아감                                         | 양 끝이 막히면 대기하며 길이 열리면 재개                                                     |

예측 상태는 움직이는 플레이어와 위치만 복사하고 맵/판정 엔티티는 읽기 전용으로 공유한다. 몬스터 보간 위치는 스냅샷별 Map으로 조회해 매 프레임의 반복 검색을 줄였다. 수신 상태 전체를 동결한 테스트로 예측과 승인 보정이 원본을 변경하지 않는지 검사한다.

## 검증 방법

```sh
npm run typecheck
npm test
npm run benchmark
npx playwright install chromium
npm run test:e2e
```

Linux의 설치된 Chromium은 `PLAYWRIGHT_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`로 선택한다. E2E 명령은 먼저 제품을 빌드한 뒤 개발 화면과 별도로 실행한 빌드 서버를 검사한다. 브라우저 테스트는 한 worker로 수행한다. 생성 이미지·음원·측정 JSON은 `test-results/`에 저장하며 Git에 포함하지 않는다.

- 공통 엔진: 벽/상자/모서리 충돌, 물풍선 탈출·연쇄·물줄기 만료, 아이템·갇힘·재생성, 몬스터 처치/전달·콤보/황금·추격·상한/대기열·종료 후 불변성. 3개 시드의 180초 경기 동안 무작위 양측 입력으로 충돌·유일 ID·점수 단조 증가·개체/대기열 상한을 반복 확인한다.
- 방/서버: 실제 Socket.IO 연결, 같은 방의 양측 상태, 인원 제한·다른 방 분리·동시 준비·재대결·잘못된/중복/이전 라운드/과다 입력·타임아웃·기권·토큰 보호. 반복 생성/나가기 후 방·연결·세션·요청 제한 버킷 정리를 확인한다.
- 지연: 공통 서버와 클라이언트 타임라인 사이에 편도 180ms, ±40ms 변동 및 중복/오래된 패킷을 넣는 결정적 시뮬레이션. 60FPS와 10FPS에서 이동 후 정지 위치의 수렴을 확인한다. 이는 실제 인터넷 회선을 이용한 테스트가 아니다.
- 브라우저: 기존 로컬/온라인 2인 플레이·결과·재대결·새로고침 복구·그림/소리 검사. 빌드 서버를 실제 종료한 뒤 연결 끊김과 입력 버튼 비활성화를 확인하고, 같은 포트에 새 서버를 띄워 만료 안내→세션 삭제→새 방 생성을 검사한다. 반복 경기 진입/이탈 후 캔버스 제거도 확인한다.

## 성능 측정의 범위

Node.js 24.19.0 클라우드 환경에서 2026-11-03에 측정한 값이다. 동일 명령도 시스템 부하와 GC에 따라 변한다.

| 측정                                       | 관측값                                                           |
| ------------------------------------------ | ---------------------------------------------------------------- |
| 180초 공통 엔진, 최대 몬스터 44마리        | 전체 117ms / 틱 p95 0.050ms                                      |
| 20개 방, 180초, 30Hz 판정·20Hz 스냅샷 생성 | 전체 1,874ms / 틱 p95 0.777ms / p99 1.219ms                      |
| 몬스터 44마리 수신·이동 예측·보간          | 3,000회 / 회당 p95 0.101ms                                       |
| 방 종료·만료 후 정리                       | 방·연결·세션·요청 제한 버킷 모두 0                               |
| 20개 방 측정 전후 GC 힙 차이               | +2.36MiB (JIT/공용 캐시 포함, 장기 누수 판정 아님)               |
| 헤드리스 대전 화면 rAF 관측 (3.03초)       | 평균 21.1회/초 / 간격 p95 66.6ms (SwiftShader 소프트웨어 렌더링) |

동일 클라이언트 측정의 수정 전 p95는 0.294ms였다. 이 예측 벤치마크는 승인값을 0으로 유지해 미승인 입력이 최대 120개 쌓인 상황을 포함한다. 수신 스냅샷 복사 비용은 회당 p95 구간 밖에서 측정되며 전체 경과 시간에는 포함된다.

`scripts/benchmark.ts`는 180초 시뮬레이션 1개, 같은 시드의 방 20개(서버 30Hz/스냅샷 생성 20Hz), 몬스터 44마리 상태의 수신/이동 예측/보간 3,000회를 측정한다. 실제 시간을 기다리지 않고 고정 스텝으로 실행한다. 방 테스트에는 소켓 직렬화·압축·네트워크 송수신이나 화면 렌더링 비용이 포함되지 않으며, 이를 동시 접속 수 보장으로 해석하지 않는다. `totalWallMs`는 루프의 경과 시간이며 OS CPU 사용률이 아니다. 종료 후 카운트와 GC 후 힙 차이도 기록하지만 단일 힙 측정은 장기 누수 검증을 대체하지 않는다.

브라우저 성능 테스트는 실제 대전 화면의 requestAnimationFrame 간격을 3초간 수집하고 `browser-performance.json`을 첨부한다. 소프트웨어 렌더링 클라우드 환경의 관측치이며 FPS를 합격 조건으로 사용하지 않는다. 일반 PC에서의 60FPS 목표 확인에는 실제 GPU/Windows Chrome·Edge 측정이 필요하다.

## 최종 실행 결과

2026-11-03, Node.js 24.19.0과 시스템 Chromium에서 타입 검사·빌드·Vitest 74개·Playwright 16개가 통과했다. 브라우저 전체 실행은 2.3분이며, 실제 서버 종료/재시작 복구와 두 브라우저의 대전·재접속·재대결이 포함된다. 낮은 FPS/지연·무작위 전체 경기·방 정리 회귀 테스트도 모두 통과했다.

성능 JSON 파일 저장과 완료 단계 표시 변경 후 메뉴/좁은 화면/반복 세션·성능 검사 3개도 다시 통과했다. 브라우저 측정 결과는 `test-results/qa-final/` 아래 `browser-performance.json`에 보존된다. 이 환경의 소프트웨어 렌더링 관측은 60FPS 목표에 미달하며, 실제 GPU가 있는 PC의 성능은 별도 확인 대상이다.

로컬 포트 바인딩과 Chromium 실행에는 클라우드 샌드박스 밖의 실행 권한이 필요하다. 환경 연결과 자동 승인 검토가 정상화된 뒤 전체 검증을 완료했다.
