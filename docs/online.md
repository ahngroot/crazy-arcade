# 각자 PC에서 즐기는 온라인 1:1 대전

## 접속과 조작

1. 호스트 PC에서 Windows EXE를 실행하거나 소스로 `npm ci`, `npm run dev`를 실행한다. EXE는 Node.js 설치가 필요 없다.
2. 각자의 PC 브라우저에서 같은 서버의 게임 페이지를 열고 **온라인 대전**을 누른다.
3. 생성자는 닉네임과 경기 시간(기본 180초/짧게 30초)을 정하고 **방 만들기**를 누른다. 8자리 방 코드나 초대 링크를 복사해 공유한다.
4. 참가자는 닉네임과 코드를 입력해 참가한다. 생성자는 빨강, 참가자는 초록이다. 두 사람 모두 **READY**를 누르면 경기장을 열고 중앙에 3→2→1을 표시한다. 3초 뒤 Game Start!와 함께 조작과 경기 시간이 시작한다. 세 번째 참가자는 거부된다.
5. 온라인에서는 팀과 무관하게 각자 **방향키**로 자신의 캐릭터만 움직인다. **Space**로 물풍선을 설치하고, **Ctrl**(왼쪽/오른쪽 모두)로 획득 순서대로 다음 아이템 하나를 사용한다. 사용 아이템은 합계 2개까지 보유한다. Ctrl을 누르고 있어도 반복 소비하지 않는다. 양쪽 Ctrl을 겹쳐 눌러도 하나의 버튼처럼 처리한다. WASD·Enter 조작과 한 PC의 로컬 2인 플레이는 제거했다. 별도의 1인 연습 모드는 메뉴에서 혼자 시작할 수 있다.
6. 결과 화면에서 두 사람 모두 **재대결 준비**를 눌러야 새 경기가 시작한다. 메뉴로 돌아가면 방에서 나가며 진행 중 경기는 기권 처리된다.

Windows EXE는 한 사람만 실행한다. 호스트는 화면의 **상대 PC에서 열 주소**와 방 코드 또는 **초대 링크 복사**를 상대에게 보낸다. 초대 링크에는 localhost 대신 선택한 LAN 주소와 방 코드가 들어간다. 상대 PC에서는 받은 주소를 브라우저에 열고 참가한다. 상대가 EXE를 따로 켜면 별개의 서버가 생겨 같은 코드로 만날 수 없다. 네트워크 어댑터가 여러 개면 상대와 연결된 주소를 고른다. 주소를 감지하지 못했을 때 localhost 링크를 복사하는 대신 호스트 IP를 안내한다.

현재 공개 인터넷 주소는 배포하지 않았다. EXE는 같은 LAN에서 기본 3001(사용 중이면 자동 배정) 포트를 사용하고, 소스 개발은 5173을 사용한다. 호스트의 해당 포트에 Windows 사설 네트워크 방화벽 접근이 허용되어야 한다. 다른 네트워크의 두 PC는 둘 다 접속 가능한 공통 서버 주소가 필요하다. Codex 클라우드의 내부 IP/localhost는 사용자 PC에서 직접 접근하는 공개 미리보기가 아니다.

빌드 후 `npm start`는 정적 클라이언트와 Socket.IO를 같은 포트(기본 3001)에 제공한다. 클라이언트에는 서버 주소를 하드코딩하지 않았으므로 HTTPS 배포 시 같은 출처의 HTTPS/WSS를 사용한다. 개발 서버와 빌드 서버를 같은 3001 포트에서 동시에 실행하지 않는다.

## 상태와 재접속

- `WAITING → READY → COUNTDOWN → PLAYING → FINISHED`. COUNTDOWN에 새 라운드 ID와 초기 경기 상태를 준비해 양쪽 경기장에 표시하고, 이 3초 동안 게임 시간·몬스터·판정·아이템 소비는 멈춘다. COUNTDOWN 중 연결 끊김/나가기는 준비한 상태를 버리고 대기실로 돌아간다. 한 명뿐이거나 상대가 끊긴 상태에서는 준비/시작할 수 없다. 결과 후 두 사람의 새 준비로 다음 COUNTDOWN을 진행한다.
- 연결이 끊기면 입력을 즉시 비우고 자리를 30초 예약한다. 경기 중에는 양쪽 시뮬레이션을 일시 중지하고 재접속 안내를 표시한다. 카운트다운 중 끊기면 취소하며 복구 후 둘 다 다시 준비해야 한다.
- 새로고침하거나 같은 탭에서 다시 접속하면 `sessionStorage`의 32바이트 난수 토큰으로 원래 자리와 최신 경기 상태를 복구한다. 활성 연결을 다른 연결이 토큰만으로 덮어쓸 수 없다. 토큰은 자기 입장 응답에만 포함되고 다른 플레이어에게 보내는 스냅샷·초대 링크에는 포함되지 않는다. 토큰은 비밀번호와 같은 자격 증명이므로 타인과 공유하지 않는다.
- 예약 자리도 2명 제한에 포함한다. 유예 시간 초과나 명시적 나가기는 기권 처리한다. 남은 사람은 결과를 보고 새 상대가 참가하면 다시 준비할 수 있다. 새 탭/다른 브라우저에는 원래 탭의 토큰이 없으므로 기존 자리를 자동 복구하지 않는다.
- 완전히 빈 방은 60초 뒤 삭제한다. 방·토큰·경기는 서버 메모리에만 있으며 서버 재시작 시 사라진다. 클라이언트는 연결 끊김을 표시하고 복구를 시도하며, 서버에 기존 방이 없으면 대기 화면에서 다시 방을 만들어야 한다.

## 판정과 동기화

아이템 입력은 단일 boolean `useItem`이다. 클라이언트는 어떤 아이템을 소모할지 지정하지 않으며 서버가 현재 보관 칸의 맨 앞 아이템과 사용 가능 상태를 판정한다. 이전 Q/E/R·J/K/L 입력은 사용하지 않는다. 빠른 Ctrl 전환은 송신 시점까지 순서대로 보존하고 수신 시퀀스로 중복 사용을 막는다.

- `apps/server/src/rooms.ts`가 멤버십, 상태 전이, 입력 검증과 공통 경쟁 엔진을 소유한다. 기존 2/3단계 엔진을 재사용하며 별도 서버 전투 규칙을 만들지 않는다.
- 서버 스케줄러 30Hz에서 공통 60Hz 고정 스텝을 진행하고, 20Hz 스냅샷에 서버 tick·시간·라운드 ID·처리한 입력 시퀀스를 포함한다. 입력 타임아웃은 300ms이며 브라우저가 숨겨져 송신이 멈춰도 이동 입력이 남지 않는다. 온라인 경기는 단순히 탭을 숨겼다고 멈추지 않는다. 실제 연결이 끊기면 재접속 유예로 일시 중지한다.
- 클라이언트는 약 30Hz로 방향과 버튼만 전송한다. 물풍선/특수 아이템의 누름·뗌 전환은 신뢰성 있는 전송을, 지속 이동 샘플은 오래된 전송이 쌓이지 않도록 volatile 전송을 사용한다. 낮은 렌더링 FPS에서는 누적 시간을 기준으로 송신·예측하며 프레임당 최대 250ms만 처리한다. 서버는 순서가 뒤처지거나 중복된 시퀀스·이전 라운드 입력을 거부하고 빠른 탭을 한 번만 처리한다.
- 자기 이동은 같은 충돌 함수를 이용해 예측하고, 스냅샷 승인 이후 미처리 입력만 재적용한다. 작은 오차는 약 65ms 계수로 보정하며 재생성 같은 큰 위치 변경은 즉시 적용한다. 다른 플레이어와 몬스터 위치는 약 100ms 버퍼로 보간한다. 물풍선·폭발·점수·아이템·피격·몬스터 사망은 예측으로 확정하지 않는다.
- 정상 렌더링 목표는 60FPS지만 프레임 수나 WAN 지연에 대한 보장은 아니다. 서버 과부하 시 프레임당 최대 250ms만 시뮬레이션하므로 경기 시간도 느려질 수 있다. 부하 테스트와 다중 서버는 이후 QA/운영 범위다.

## 입력 및 접근 제한

닉네임은 문자·숫자·공백·밑줄·하이픈으로 1~16자이며 화면에는 textContent로 표시한다. 방 코드는 암호학적 난수로 충돌 검사 후 만든다. 생성/입장/복구 요청은 IP당 분당 60회, 준비 변경은 소켓당 분당 60회, 이동 입력은 소켓당 초당 90회 제한한다. 공유 IP에서는 제한도 공유된다. 방은 최대 200개다.

방향은 -1/0/1, 버튼은 boolean, 시퀀스는 증가하는 정수, 라운드 ID는 현재 값인지 검사한다. 클라이언트가 보낸 임의 점수나 위치는 판정에 사용하지 않는다. 같은 출처의 Socket.IO 연결만 허용하며 브라우저 밖의 Origin 없는 통신은 테스트/직접 클라이언트를 위해 허용한다. 이는 회원 인증 시스템이 아니며 비공개 방의 접근 수단은 방 코드다. 세밀한 운영 보안·프록시 정책·부하 검증은 배포 단계에서 다룬다.

## 검증

`npm run typecheck`, `npm test`, `npm run build`, `PLAYWRIGHT_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`.

검증 범위: 서버 상태 전이·인원 제한·다른 방 분리·기권·만료/정리·세션 탈취 방지·중복/비정상/과다 입력·입력 타임아웃·전체 라운드/재대결, 실제 Socket.IO 연결·양측 상태 일치, 클라이언트 이동 예측·승인 보정·보간. 브라우저 검사는 별도 컨텍스트 두 개의 실제 플레이, 세 번째 사용자 거부, 코드/초대 링크 복사, 한 탭 이탈 후 복구, 동일 결과와 재대결·명시적 기권을 확인한다. 인터넷의 서로 다른 실제 PC 두 대와 고지연·저속 회선, 공개 HTTPS 접속은 아직 검증하지 않았다.
